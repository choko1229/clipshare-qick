# MANUAL_TESTS（実機での確認手順）

自動テストでは確認できない項目（実機の Windows 11・エクスプローラー・SteamVR・MSIX・VRChat）の手順。
`PROGRESS.md` で `[H]`（実機確認待ち）の項目は、ここで確認して `[x]` にする。

## 0. 準備

| 必要なもの | 備考 |
|---|---|
| Windows 11（23H2 以降） | 右クリック拡張は Windows 11 の最上位メニューのみ対応 |
| Windows SDK | `makeappx.exe` / `signtool.exe`（`installer/README.md`） |
| テスト用の署名済み MSIX と `.cer` | `installer/README.md` の手順 1・2 |
| VRChat（デスクトップ / VR）、SteamVR、HMD | §6・§7 |
| モックサーバー（本番を使わない確認用） | `cargo run -p cq-mock-server -- 8787` |

本番の Clipshare に実際にアップロードする確認（§8）は、テスト用のアカウントを用意してから行う。

### 本番を使わずに確認する方法（モックサーバー）

1. `cargo run -p cq-mock-server -- 8787` を起動する。
2. `%LOCALAPPDATA%\ClipshareQuick\settings.json` を作り、`{"advanced":{"apiBaseUrl":"http://127.0.0.1:8787"}}` と書く（BOM なしの UTF-8）。
   - 設定ファイルの形式が不正だと退避（`settings.broken.json`）して既定値（本番の URL）で起動するので注意。
3. モックの台本でエラーを再現できる（例: 次のアップロードを 503 にする）。
   ```powershell
   Invoke-RestMethod -Method Post http://127.0.0.1:8787/__mock/script/quick -Body '{"type":"error","status":503,"code":"SERVICE_UNAVAILABLE"}'
   ```
   - 1日上限: `{"type":"error","status":429,"code":"DAILY_LIMIT_EXCEEDED","details":{"resetsAt":"2026-12-01T15:00:00Z"}}`
   - サイズ超過（画像）: `{"type":"error","status":413,"code":"SIZE_LIMIT_EXCEEDED","details":{"limitBytes":10,"kind":"IMAGE"}}`
   - 連携切れ: `Invoke-RestMethod -Method Post http://127.0.0.1:8787/__mock/revoke`
   - nginx の HTML 413: `{"type":"raw","status":413,"content_type":"text/html","body":"<html>413</html>"}`
   - BAN・トークン発行の停止: `/__mock/config` で `banned` / `tokenIssuancePaused` を `true` にする

## 1. インストール（画面 02・03）〔PROGRESS Step 5〕

1. テスト用 PC（または Windows サンドボックス）に `.cer` を信頼させる（`installer/README.md` §3）。
2. `ClipshareQuick-Setup-x.y.z.exe` と `.msix` を同じフォルダに置き、セットアップを起動する。
3. 確認:
   - [ ] ようこそ → 使用許諾（チェックするまで「次へ」が押せない）→ オプション（4 項目、既定は上 3 つ ON）
   - [ ] 自己署名の場合だけ「署名について（暫定）」が出て、発行者と拇印が `.cer` と一致する
   - [ ] インストール中の進捗（%）と手順の表示。右クリック・SteamVR を OFF にした場合はその手順が表示されない
   - [ ] 完了画面の「Clipshare Quick を起動して初回設定を開始する」で初回設定が開く
   - [ ] 「右クリックメニューに表示されない場合…」の「再起動」でエクスプローラーが再起動する
   - [ ] 失敗時（例: 署名を信頼しない状態でインストール）に画面 03 ⑦ が出て、「再試行」「オプションを変えて再試行」「ログを開く」が動く
4. `.msix` を直接ダブルクリックした場合（App Installer）でもインストール・起動できる。

## 2. 初回セットアップ（画面 04・05・06）

1. 初回起動で画面 04 が出る。
   - [ ] 「手動でのみ使う」を選ぶと、写真を撮っても自動では送られない
   - [ ] 「自動アップロードを有効にして続ける」を選ぶと、以後の写真が送られる
2. 画面 05
   - [ ] VRChat の `config.json`（`%USERPROFILE%\AppData\LocalLow\VRChat\VRChat\config.json`）に `picture_output_folder` を設定している場合、そのフォルダが「検出しました」になる（SPEC §6 の未検証項目）
   - [ ] 設定していない場合は `ピクチャ\VRChat`。フォルダが無い場合は「見つかりませんでした」と「選択」（フォルダは作られない）
3. 画面 06
   - [ ] ブラウザが開き、Clipshare の認可画面とアプリの接続コード（`XXX-XXX`）が一致する
   - [ ] 許可 → 「連携しました」とユーザー名。キャンセル → 「連携できませんでした」と `ACCESS_DENIED`
   - [ ] 5 分放置 → `AUTH_TIMEOUT`。「ブラウザを開き直す」「あとで連携する」が動く
   - [ ] 資格情報マネージャー（`control /name Microsoft.CredentialManager` → Windows 資格情報）に `ClipshareQuick:token:clipshare.link` がある。値はアプリ以外から見えない
4. 起動前から写真フォルダにあった写真がアップロードされない。

## 3. 自動アップロード・トレイ・履歴（画面 08・09・16）

1. VRChat で写真を撮る（または写真フォルダの年月サブフォルダに画像をコピー）。
   - [ ] 書き込みが終わってから 1 回だけ送られる（同じ写真が 2 回送られない）
   - [ ] 共有URL（`/q/{id}`）がクリップボードに入り、通知「共有URLをコピーしました」が出る。通知の「開く」「削除」が動く
   - [ ] 続けて撮ると、通知が「N件のURLをコピーしました」にまとまり、クリップボードは改行区切り
2. トレイ
   - [ ] アイコンの状態: 待機中（緑）／アップロード中（回転）／エラーあり（赤い点）／一時停止（グレー）／要ログイン（黄色の点）
   - [ ] 左クリックで履歴パネルが右下に開き、ほかをクリックすると閉じる。右クリックでメニュー（履歴を開く・自動アップロード・設定…・Webで管理・終了）
3. 履歴パネル
   - [ ] URL のコピー・ブラウザで開く・削除（削除後は「削除済み」）、失敗の「再試行」、期限切れ（24 時間後）の表示と「履歴から消す」
   - [ ] 未ログインのとき「未ログインで利用中 今日 N / 5 件」と「ログインして制限を解除」
   - [ ] ネットワークを切る → 「オフラインです…待機中のN件」→ 戻すと自動で送られる
4. 1日上限（未ログインで 6 枚目）
   - [ ] 通知「今日の上限（5件）に達しました」、トレイが一時停止。停止中に撮った写真は、翌日になっても送られない
5. 利用停止（403。管理画面で BAN、またはモックの `banned`）
   - [ ] 通知「このアカウントでは利用できません」と「お問い合わせ」。履歴パネル・設定アカウントに同じ帯と「お問い合わせ」（お問い合わせページが開く。URL は暫定値 `/contact`、Q-027）
   - [ ] 「ログインして連携」「再ログイン」「再試行」が出ない。403 で失敗した項目に「再試行」が無い。匿名でも送られない
   - [ ] 初回セットアップで BAN 済みのアカウントを許可した場合、「連携できませんでした」と 403 の説明、「お問い合わせ」（「もう一度試す」は出ない）
6. 連携切れ（Web の「連携アプリ」（`/settings/apps`）で解除）
   - [ ] 通知「連携が切れました」、トレイが要ログイン。**匿名で送られない**。「再ログイン」で直る
7. サイズ超過
   - [ ] 上限を超える画像は長辺 2000px に縮小して送られ、通知「サイズが大きいため縮小しました」
   - [ ] 上限を超える動画は「動画は縮小できないため送れませんでした」
8. 表示
   - [ ] ライト／ダーク（Windows の設定 → 個人用設定 → 色）で配色が切り替わり、文字が読める（SPEC §6 のライトテーマのコントラスト）
   - [ ] 拡大率 100%／150%／200% で表示が崩れない。日本語が欠けない

## 4. 設定（画面 10・11・12）

- [ ] 新規インストール（設定ファイルなし）で、設定「アップロード」の既定の画質が「縮小（長辺2000px）」、履歴パネルの画質も「縮小」（Q-011）
- [ ] 以前のバージョンで「原寸」を選んでいた設定ファイルを残したまま更新しても「原寸」のまま

- [ ] 変更がすぐ反映される（再起動不要）。例: 自動アップロード OFF で撮っても送られない、画質の変更が次の送信に反映される
- [ ] 「ログアウト」でサーバー側のトークンが失効し、資格情報マネージャーからも消える。オフライン時は「連携の解除が完了していません」
- [ ] 写真フォルダの追加・削除、「監視中」「見つかりませんでした」の表示
- [ ] Windows 起動時に開始（サインアウト→サインインで常駐する）。タスク マネージャーの「スタートアップ アプリ」に表示される
- [ ] 「ログを開く」でログフォルダが開く。ログにトークン・ファイルの内容・ユーザー名入りのパスが無い（`%USERPROFILE%` に置き換わっている）
- [ ] 「診断情報」の「コピー」で、個人情報を含まない概要がコピーされる

## 5. 右クリック共有（画面 14・15）〔PROGRESS Step 4〕

1. エクスプローラーで画像を 1 枚右クリック。
   - [ ] Windows 11 の最上位メニューに「Clipshareで共有」があり、サブメニュー「原寸で共有」「縮小して共有（既定）」（既定は縮小、Q-011。設定で原寸にすると「（既定）」が原寸側に移る）
   - [ ] 選ぶと進捗ウィンドウ（画面 15）が出て、完了後に URL がクリップボードに入る
2. 3 枚選択 → 「Clipshareで共有（3件）」
   - [ ] 3 件を順に送り、URL が改行区切りでクリップボードに入る。「履歴を開く」「閉じる」
3. 動画を選択
   - [ ] サブメニューが無く、そのまま共有される
4. 一部失敗（上限を超える動画を混ぜる）
   - [ ] 「2件完了・1件失敗」と失敗理由が出る
5. アプリを終了した状態で右クリック共有
   - [ ] アプリが起動して共有される（エクスプローラーが固まらない）
6. 設定 → 一般 → 右クリックメニュー OFF
   - [ ] メニューが表示されなくなる
7. エクスプローラーを再起動しても動く。ネットワークドライブ（UNC）上のファイルは共有されない

## 6. SteamVR（画面 18・19）〔PROGRESS Step 4〕

準備: `openvr_api.dll`（OpenVR SDK の `bin/win64`）をパッケージに同梱する（`installer/README.md` §2）。

- [ ] SteamVR を起動していない状態でもアプリが普通に動く
- [ ] SteamVR を起動すると、約 5 秒以内に接続する（ログに「SteamVR に接続しました」）
- [ ] VRChat で撮影 → 視界内に「アップロード中…」→「URLをコピーしました 24時間有効 · 1件」が 3 秒ほど出て消える
- [ ] エラー時に「アップロードできませんでした」、自動アップロード OFF で「自動アップロード OFF 撮影してもアップロードしません」
- [ ] ダッシュボードに「Clipshare Quick」パネル。自動アップロードの切り替え、直近の写真のサムネイル、削除（確認ダイアログ「この写真を削除しますか？」）、失敗の再試行
- [ ] VR 内にログ・トークン・ファイルのパスが表示されない
- [ ] SteamVR の設定 → 起動時に開始するアプリに Clipshare Quick がある（インストール時に「SteamVRに登録する」を選んだ場合）。設定で SteamVR を OFF にすると登録が外れる
- [ ] SteamVR を終了してもアプリが落ちない（再度起動すると再接続する）

## 8. 更新（画面 21）〔PROGRESS Step 5〕

Clipshare 側の `GET /api/v1/client/latest` が新しい版を返す状態で確認する（モックなら `/__mock/config` で `latest` を設定）。

- [ ] 起動から約 20 秒後と 24 時間ごとに確認し、通知「新しいバージョンがあります」が出る（勝手にダウンロード・適用しない）
- [ ] 「ダウンロードして更新」→ 進捗 → 「更新の準備ができました 署名を確認しました」
- [ ] `sha256` を 1 文字変えた `latest` → 「更新できませんでした 署名の確認に失敗しました」、今のバージョンのまま使える
- [ ] 古いバージョンを返す `latest` → 通知されない（ダウングレードしない）
- [ ] 「今すぐ再起動して更新」→ アップロード中なら終わってから更新され、アプリが再起動する
- [ ] 右クリックメニューを一度使った後（エクスプローラーが拡張を読み込んでいる状態）で更新 → 「PCを再起動すると更新されます」になり、再起動後に更新されている（SPEC §6 の未検証項目）
- [ ] 「次回起動時に更新」→ アプリ終了後の次回起動で新しい版

### 8.1 sha256（契約 v1.2）
- [ ] `latest` の `sha256` が一致 → 「署名を確認しました」まで進む
- [ ] `sha256` を 1 文字変える → 「署名の確認に失敗しました」、ダウンロードしたファイルが `%LOCALAPPDATA%\ClipshareQuick\downloads` に残らない
- [ ] `sha256` が null（契約上は発生しない想定）→ 通知は出るが自動では入れず、画面 21 の「更新履歴」でダウンロードページへ案内

## 9. アンインストール（画面 22）〔PROGRESS Step 5〕

設定 → 一般 →「アンインストール」から行う（Q-009）。

- [ ] 3 つの選択肢（設定と履歴／連携解除／アップロード済みの即時削除）がそれぞれ効く
- [ ] オフラインで実行 → 「連携の解除が完了していません」と「連携アプリを開く」
- [ ] 「完了」後、パッケージが削除され、スタートメニュー・右クリックメニュー（エクスプローラー再起動後）・SteamVR の登録・資格情報マネージャーのトークンが残らない
- [ ] Windows の設定から直接アンインストールした場合も、アプリが削除される（サーバー側のトークンは Web から解除できる）

## 9.1 自己署名の導線（2 ファイル配布）

1. `installer/signing.json` の Publisher で証明書を作り（`new-dev-certificate.ps1`）、`CQ_SIGNING_CER` を指定してビルド、`build-msix.ps1` で署名する（`installer/README.md`）。
2. テスト用 PC（証明書を信頼していない状態）に **セットアップ exe と MSIX の 2 ファイルだけ**を置いてセットアップを起動する。
   - [ ] 「署名について（暫定）」に表示される発行者・拇印が、作成した証明書と一致する（`.cer` を同じフォルダに置かなくても表示される）
   - [ ] 「この署名を信頼して…」に同意 → UAC → 「ローカル コンピューター\信頼されたユーザー」に証明書が入り、インストールが進む
   - [ ] UAC で「いいえ」→ `CERT_TRUST_CANCELLED` の失敗画面。「再試行」で再度 UAC が出る
   - [ ] 一度信頼した後の「再試行」では UAC が出ない
   - [ ] 終了後、`%TEMP%` に `ClipshareQuick-*.cer` が残らない（信頼に成功した場合）

## 9.2 データフォルダのアクセス権と履歴の削除用トークン

- [ ] 起動後、`icacls "%LOCALAPPDATA%\ClipshareQuick"` が「利用者・SYSTEM・Administrators」の 3 つだけで、`(I)`（継承）が無い
- [ ] 右クリック拡張（エクスプローラー）から設定の既定画質が読める（「（既定）」の表示が設定どおり）
- [ ] 未ログインでアップロード → `history.json` に `deleteToken` がある。24 時間後（または期限を過ぎた状態で起動）に `deleteToken` が消えている
- [ ] 履歴から削除した項目の `deleteToken` が消えている。ログ（`logs\`）に `deleteToken` の値が出ていない
- [ ] `history.json` をわざと壊して起動 → 空の履歴で起動し、壊れたファイルと `.history.json.*.tmp` が残らない
