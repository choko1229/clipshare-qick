## 環境・調査メモ（Step 0 で記入）

- 作業開始時点（2026-11-20）の開発機には Rust・MSVC（Visual Studio Build Tools）・Windows SDK がいずれも無かった。
- システム全体に影響しないよう、次の 2 つだけをユーザー領域に導入した（PATH・レジストリは変更していない）。
  - rustup（`%USERPROFILE%\.rustup`・`.cargo`、`--no-modify-path`、ホスト `x86_64-pc-windows-gnu`、ツールチェーン 1.100.0）
  - WinLibs の MinGW-w64（GCC 16.2 / binutils、MSVCRT 版、`%USERPROFILE%\.cq-devtools\mingw64` に展開しただけ）
- rustup 単体の GNU ツールチェーン（自己完結リンカー）では `windows-link` の raw-dylib 用 `dlltool` が `as` を見つけられずに失敗し、
  LLVM の dlltool で代用すると依存が増えた段階で起動時にアクセス違反になった。正規の binutils（WinLibs）で解消。
- CI（GitHub Actions `windows-latest`）は MSVC ツールチェーンでビルドする。ローカルの GNU ビルドと CI の MSVC ビルドの両方で通ることを確認する方針。
- Windows SDK が無いため、ローカルでは `makeappx` / `signtool` による MSIX 作成・署名ができない。手順書（`installer/README.md`）と CI 用スクリプトまでを用意する。
- 開発者向けの環境構築手順は `README.md` の「開発」に記載。

## Q-001 (2026-11-20) 開発ツールチェーン（GNU と MSVC）
- 状況: 開発機に MSVC が無く、Visual Studio Build Tools の導入はシステム全体に影響する（管理者権限・システム領域へのインストール）。
- 選択肢と採用した暫定案（理由）:
  1. VS Build Tools を入れて MSVC で開発 — システム全体に影響するため自走では行わない。
  2. **GNU ツールチェーン + ユーザー領域の MinGW-w64 で開発し、CI とリリースは MSVC**（採用）。コードは C 依存を持たない構成（TLS は Windows 標準の schannel、画像処理は純 Rust）にしたので、どちらでも同じソースでビルドできる。
- 影響範囲: ビルド手順、CI。リリース成果物は CI（MSVC）で作る。
- 人に確認したいこと: 開発機に VS Build Tools と Windows SDK を入れてよいか（入れれば MSIX のローカル作成・署名まで確認できる）。
- 状態: 未確認

## Q-002 (2026-11-20) UI フレームワークの選定
- 状況: INSTRUCTIONS §2「候補と理由を提示して承認を得てから採用」。自走ルールにより暫定決定して進める。
- 候補:
  | 候補 | Windows親和性 | 日本語 | トレイ | 保守性・その他 |
  |---|---|---|---|---|
  | **egui / eframe（glow）** | ○ OpenGL(WGL)。追加ランタイム不要 | ○ システムの日本語フォント（Yu Gothic UI / Meiryo）を読み込んで表示。IME 対応あり | ○ `tray-icon` と同じスレッドで共存（Win32 メッセージループを共有） | 純 Rust（C コンパイラ不要）、MIT/Apache-2.0、依存が少なくビルドが速い。即時モードなので状態とUIの対応が単純でテストしやすい |
  | Slint | ○ | ○ | △ 別クレート併用 | 宣言的で見た目を作り込みやすいが、ロイヤリティフリーライセンスは表記義務あり（MIT 公開アプリとして扱いが複雑） |
  | Tauri（WebView2） | ○ WebView2 は Win11 標準 | ◎ デザインのHTMLをほぼ流用できる | ○ | リソースコンパイラ（rc.exe/windres）や Web フロントのビルドが必要で依存が重い。常駐アプリとしてはメモリ消費が大きい |
  | Win32 直書き（windows クレート / native-windows-gui） | ◎ | ○ | ○ | 最もネイティブだが、デザイン（角丸カード・トグル等）の再現に描画コードが大量に必要で保守性が低い |
- 採用した暫定案: **egui / eframe 0.31（glow）**。理由: 純 Rust で依存が軽い、ライセンスが MIT と相性が良い、トレイ常駐と同居しやすい、デザイン（カード・トグル・セグメント・バッジ）をテーマ設定で再現できる。
  - ウィンドウは「必要なときだけ開く」方式（`run_and_return`）。トレイ常駐中はウィンドウを持たず、Win32 メッセージループだけが回る。
  - フォントは `C:\Windows\Fonts` の Yu Gothic UI → Meiryo → MS Gothic の順に読み込む（デザインの LINE Seed JP は再配布ライセンスの確認が要るため同梱しない）。
- 影響範囲: `crates/app` 全体。
- 人に確認したいこと: egui の採用でよいか。LINE Seed JP を同梱したい場合は SIL OFL の表記を「情報」タブに入れる必要がある。
- 状態: 未確認
