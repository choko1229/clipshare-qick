## 環境・調査メモ（Step 0 で記入）

- 作業開始時点（2026-11-20）の開発機には Rust・MSVC（Visual Studio Build Tools）・Windows SDK がいずれも無かった。
- システム全体に影響しないよう、次の 2 つだけをユーザー領域に導入した（PATH・レジストリは変更していない）。
  - rustup（`%USERPROFILE%\.rustup`・`.cargo`、`--no-modify-path`、ホスト `x86_64-pc-windows-gnu`、ツールチェーン 1.100.0）
  - WinLibs の MinGW-w64（GCC 16.2 / binutils、MSVCRT 版、`%USERPROFILE%\.cq-devtools\mingw64` に展開しただけ）
- rustup 単体の GNU ツールチェーン（自己完結リンカー）では `windows-link` の raw-dylib 用 `dlltool` が `as` を見つけられずに失敗し、
  LLVM の dlltool で代用すると依存が増えた段階で起動時にアクセス違反になった。正規の binutils（WinLibs）で解消。
- CI（GitHub Actions `windows-latest`）は MSVC ツールチェーンでビルドする。ローカルの GNU ビルドと CI の MSVC ビルドの両方で通ることを確認する方針。
- Windows SDK が無いため、ローカルでは `makeappx` / `signtool` による MSIX 作成・署名ができない。手順書（`installer/README.md`）と CI 用スクリプトまでを用意する。
- 開発者向けの環境構築手順は `README.md` の「開発」に記載。
