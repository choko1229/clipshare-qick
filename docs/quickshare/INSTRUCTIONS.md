# 指示書 2/2: Windows クライアント「Clipshare Quick」（Rust）

> 取り込み補足: 本ファイルは作業パックに合わせて配置済み。実装順・自走ルールは `CLAUDE.md` と `PROGRESS.md` を優先する。

目的: VRChat で写真を撮ると自動で Clipshare にアップロードし、共有URL（`/q/{id}`）をクリップボードへ。エクスプローラー右クリックでも発行。SteamVR 通知/パネル、インストーラー、更新を備える。
前提: **指示書 1/2（Clipshare 改修）が完了・本番反映済み**で、`/api/v1/*` が使えること。API 仕様は同書 §3 に従い、差異があれば質問する。
参照: 仕様書Doc、UIデザインキャンバス（クライアント画面 02–06, 08–12, 14–16, 18–19, 21–22）。
開発環境: Windows（実機）。ソースは MIT ライセンスで公開、GitHub Releases で配布。UI は日本語のみ。

---

## 0. 進め方の前提（必ず守る）
- 不明点は**実装せず質問**。仕様にない機能を足さない（QR 表示、手首オーバーレイ、OSC 連携は**スコープ外**）。
- 設定は永続化（ローカル設定ファイルまたは SQLite）し、UI から変更可。ハードコードしない。
- 型を厳密に（`unsafe` は最小限・理由コメント必須）。`unwrap`/`expect` を本番経路で使わない。エラーは `thiserror`/`anyhow` で文脈付与。
- 詳細ログ（ローテーション付きファイル、レベル切替）。**ログにトークン・Authorization・ファイル内容を出さない。**
- セキュリティ最優先（§8）。
- 完了後に §10 のセルフレビューを複数回実施。

## 1. ブランチ運用
- リポジトリ（新規、MIT、公開）。`main` 保護、機能ごとに `feature/<name>` → PR → マージ。
- CI（GitHub Actions）: `cargo fmt --check`、`cargo clippy -D warnings`、`cargo test`、Windows ビルド。リリースはタグ（`vX.Y.Z`）で署名済み MSIX を GitHub Releases に添付。
- バージョニングは SemVer。`CHANGELOG.md` を維持（DLページの更新履歴に使う）。

## 2. 構成（推奨・変更は理由を添えて相談）
- 単一ワークスペース: `core`（アップロード・設定・履歴・API クライアント）、`app`（トレイ/UI/ウォッチャー）、`shell-ext`（右クリック拡張 DLL）、`vr`（OpenVR 連携）、`installer`（MSIX パッケージ定義）。
- UI は日本語のみ。UI フレームワークはメンテ性と Windows 親和性で選定し、**候補と理由を提示して承認を得てから**採用。
- 非同期ランタイム（tokio）。HTTP（reqwest, rustls）。タイムアウト・再試行・キャンセルを明示。

## 3. 機能仕様

### 3.1 初回セットアップ  〔画面 04–06〕
1. 説明と同意: 自動アップロードが既定で ON であること、ファイルが Clipshare のサーバーへ送られることを確認し同意を取る。同意しなければ何も送らない。
2. 写真フォルダ: 既定は `%USERPROFILE%\Pictures\VRChat`。**VRChat の `config.json`（`picture_output_folder`）から出力先を読めるか検証**。読めれば優先、読めなければ既定＋手動選択（未検証→要確認）。フォルダ不在は作成せず案内。
3. ブラウザ認可: 「ログイン」または「ログインせず匿名で使う」。ログインはループバック + PKCE（指示書1 §3 Step 2）。状態表示: 待機中 / 成功 / 期限切れ / キャンセル / エラー。接続コード（`7K2-M9Q` 形式）を画面にも表示しブラウザ表示と照合させる。
- **初回起動時に既に存在する過去の写真は無視**。起動後に作成されたファイルのみ対象（起動時刻 or 監視開始時点のスナップショットで判定）。

### 3.2 自動アップロード（フォルダ監視）
- `notify` 等で新規ファイルを監視（サブフォルダ `YYYY-MM` 対応）。対象は画像（png/jpg/webp）、動画は設定で有効時。
- **書き込み途中のファイルを拾わない**: 作成イベント後、サイズ/更新時刻が一定時間安定し、排他オープン可能になるまで待つ（最大待機とタイムアウトあり）。
- **重複アップロード防止**: パス+サイズ+更新時刻（またはハッシュ）で処理済み管理（履歴DB）。
- アップロード: `POST /api/v1/quick`（Bearer、トークンは Windows 資格情報マネージャーから取得）。画質は設定（原寸/縮小）。成功したら `url` をクリップボードへ（設定で ON/OFF）＋トースト＋履歴追加。
- **サイズ超過（413 `SIZE_LIMIT_EXCEEDED`）**: 画像は自動で長辺 2000px に縮小して**再送**。動画は縮小不可 → エラーとして履歴/トーストに「動画は縮小できないため送れませんでした」。
- **1日上限（429 `DAILY_LIMIT_EXCEEDED`）**: 通知して**自動アップロードを停止**、翌日に再開。**停止中に撮った写真は送らない**（キューにも積まない）。ログインすると上限が上がることを案内（匿名時）。再開タイミングは API が返すリセット時刻 or 現地日付変化で判定。
- **オフライン/障害**: 指数バックオフで自動再試行（上限回数・最大間隔を設定値に）。それでもダメなら**失敗として履歴に残し**、手動再試行ボタンを提供。オフライン復帰で自動再開。再起動後も未送信の失敗が残る（永続化）。
- 401（失効/無効トークン）: 再認可を促す通知。**匿名へ自動フォールバックしない**。

### 3.3 トレイと履歴  〔画面 08–09〕
- トレイ常駐。メニュー: 最近の履歴（直近 **50 件**）、自動アップロード ON/OFF、設定、終了。
- 履歴: URL 再コピー、サーバー側削除（`DELETE /api/v1/quick/{id}`）、失敗の再試行。**期限（24 時間）切れは「期限切れ」と表示して残す**。状態: アップロード中 / 完了 / 失敗 / 期限切れ / 削除済み。

### 3.4 設定  〔画面 10–12〕
- アップロード: 自動アップロード ON/OFF、撮影後に URL をコピー、既定の画質（原寸/縮小）。
- アカウント: ログイン状態、連携解除（`DELETE /api/v1/auth/token` + ローカルのトークン削除）、匿名利用時の案内。
- VRChat・一般: 写真フォルダ、Windows 起動時に起動、その他。
- 設定の変更は即時反映（再起動不要）。不正値は保存前に検証。

### 3.5 右クリック共有  〔画面 14–15〕
- **Windows 11 の最上位コンテキストメニュー**に表示（`IExplorerCommand` を実装した COM シェル拡張、**署名付き MSIX パッケージ**の `windows.fileExplorerContextMenus` 拡張）。画像・動画の両方が対象。
- 画質（原寸/縮小）をメニューから選択可。
- **複数選択: 全ファイルをアップロードし、URL を改行区切りでクリップボードへ**。進捗ウィンドウ（画面 15）: 進行中/完了/一部失敗、失敗ファイルに理由表示。
- 拡張 DLL はアップロード本体を持たず、本体アプリを起動（IPC：名前付きパイプ等）。拡張内で重い処理・ネットワークをしない（Explorer を固めない）。クラッシュしても Explorer を巻き込まない設計。
- Windows 10 以前のクラシックメニュー対応は仕様外。

### 3.6 Windows 通知  〔画面 16〕
- トースト: アップロード中 / 完了（URL コピー済み）/ 失敗 / 画像の自動縮小 / 動画のサイズ超過 / 1日上限（「明日から再開します。それまでに撮った写真は送りません。」）/ 自動アップロードの切替。連続撮影時は集約（スパム防止）。クリックで URL 再コピー/履歴を開く。

### 3.7 SteamVR  〔画面 18–19〕
- OpenVR オーバーレイ。**HUD トースト**（視界内の短い通知: アップロード中/完了(URL コピー)/エラー/自動アップロード切替）と**ダッシュボードパネル**（自動アップロード ON/OFF、直近の写真の削除）。
- SteamVR のマニフェスト登録/解除をインストーラーのオプションに連動。SteamVR 未起動でもアプリ本体は動作。
- スコープ外: QR コード、手首オーバーレイ、OSC。
- 実機（VRChat + SteamVR）で手動確認。VR 内でログ/トークンが表示されないこと。

## 4. トークン保管
- Windows 資格情報マネージャー（`windows` crate の Credential API 等）に保存。**平文ファイル・設定ファイル・ログ・環境変数に置かない。**
- 取得失敗/破損時は再認可フローへ。メモリ上のトークンは最小限の寿命（`zeroize` 検討）。

## 5. インストーラー・更新・アンインストール  〔画面 02, 03, 21, 22〕
- **MSIX**（インストール先は Windows が管理。UI にインストール先の変更を出さない）。署名は**まず自己署名**、公開前に正式署名を決定（要ユーザー判断）。自己署名の間は DL ページ/インストーラー画面に証明書信頼手順を表示。
- オプション（画面 02）: Windows 起動時の起動、右クリックメニュー、SteamVR 登録、ショートカット。
- **更新**: GitHub Releases（公開リポジトリ）。**更新を通知し、ユーザーが選んで適用**。VRChat プレイ中に勝手に再起動しない。確認頻度は起動時+1 日 1 回程度（未認証 API は 1 時間 60 回/IP のため）。Clipshare 側の `GET /api/v1/client/latest`（採用時）を優先利用。
  - ダウンロード後、**ハッシュ/署名を自前で検証**し、不一致は適用しない（画面 21）。
  - MSIX の `.appinstaller` 自動更新が GitHub Releases の URL で成立するかは**事前検証しない**。成立しなければ自前の更新フロー（ダウンロード→検証→`Add-AppxPackage`/App Installer 起動）で実装。
  - **右クリック拡張が Explorer に読み込まれていて更新できない場合は、再起動（Explorer 再起動 or ログオフ）を求める**（画面 21 の「今すぐ再起動/次回起動時」）。
- アンインストール（画面 22）: 設定と履歴の削除の選択、Clipshare との連携解除（`DELETE /api/v1/auth/token`、オフラインなら Web「連携アプリ」から解除する案内）、アップロード済みファイルの即時削除の選択。資格情報マネージャーのトークンを削除。拡張とオーバーレイ登録を残さない。

## 6. エラー処理・ログ
- 全てのネットワーク/ファイル/COM/OpenVR 呼び出しに型付きエラー。ユーザー向けは日本語の分かりやすい文言＋対処、ログには原因（HTTP ステータス、API エラーコード、リクエストID）。
- ログ: ローテーション、既定 INFO、設定で DEBUG。ログを開く導線あり。個人情報（ユーザー名を含むパス）はマスク検討。
- パニックはフックで記録し、トレイ常駐を可能な限り継続。

## 7. 設定値（ハードコード禁止）
再試行回数/間隔、ファイル安定待ち時間、履歴件数(50)、更新確認間隔、API ベース URL（既定は本番 Clipshare）、ログレベル。

## 8. セキュリティ要件
- 通信は HTTPS のみ・証明書検証を無効にしない。リダイレクト先のホスト検証。
- ループバック受信は 127.0.0.1/[::1] のみ・使い捨て・タイムアウト・`state` 検証・単一接続。ポートはランダム。
- 右クリック拡張の IPC は同一ユーザー限定の ACL。引数のパスを信頼せず検証（パストラバーサル、UNC、シンボリックリンク）。
- 更新ファイルの検証（ハッシュ/署名）。ダウングレード攻撃防止（バージョン比較）。
- 依存クレートは `cargo audit` / `cargo deny` を CI に。
- 送信前に必ず同意状態を確認（未同意は送らない）。

## 9. テスト
自動（ユニット/結合、モックサーバー使用）:
- 監視: 書き込み途中ファイルを拾わない、同一ファイルの重複イベントで 1 回だけ送る、起動前の既存写真を無視する。
- アップロード: 成功、413（画像→縮小再送 / 動画→エラー）、429（停止→翌日再開→停止中の写真は送らない）、401、5xx/タイムアウトの再試行と失敗の永続化、オフライン復帰。
- 履歴: 50 件上限、期限切れ表示、再コピー、削除、再試行。
- 複数選択の URL 改行連結、クリップボード内容。
- 認可: PKCE/state、タイムアウト、キャンセル、接続コード表示。
- 設定: 不正値の検証、即時反映、永続化。
- トークン保管: 保存/取得/削除、破損時の挙動。
手動（実機 Windows 11 + VRChat + SteamVR）:
- 実際に VRChat で撮影 → URL がクリップボード、トースト、履歴、VR HUD。
- 右クリック（画像/動画、単一/複数）、Explorer 再起動後も動作。
- インストール/更新/アンインストール（自己署名の信頼手順含む）、更新時に拡張が使用中のケース。
- ライト/ダーク、日本語表示崩れ、高 DPI。
